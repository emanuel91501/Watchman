# Run the Watchman engine (fresh cloud session, no state kept between runs)

Never print, echo or paste a key value. ArtifactData `url` = the Watchman artifact URL from the task prompt.

## (a) Clone and install
`git clone <repo url from the task prompt> w && cd w/engine && pip install --break-system-packages -r requirements.txt`

## (b) Keys
Create `.keys.env` with the file-write tool (not echo/cat), one `NAME=value` line per key, values from the task prompt:
DATA_GOV_API_KEY, FRED_API_KEY, EIA_API_KEY, OPENSTATES_API_KEY, BEA_API_KEY, COURTLISTENER_TOKEN

## (c) Hourly (about 40-110 s; creates only NEW docs, no reads, no versions; run step 1 with Bash timeout 300000 ms)
1. `python3 engine.py --mode hourly --out out/hourly`
2. `python3 test_engine.py --out out/hourly` (every line PASS)
3. `out/hourly/` holds `batch_001.json` (normally the only batch). For each batch_NNN.json in order: ArtifactData `action:"batch"`, `writes` = the file's JSON array, unchanged. Each write is a `set` of a new `live/<YYYY-MM-DD>T<HHMM>` doc (or `_2`, `_3`).
4. Photos (P10, R2-pub): if `out/hourly/img/manifest.json` exists, upload its files with the Artifact tool (`url`, `asset:true`, `file_paths`, up to 25 per call), then write ONE new doc `img/h<YYYY-MM-DDTHHMM>` (same stamp as the live doc; new, so no version) = `{"images":[{id, url, credit, license, src_url, taken, posted, publisher, width, height, ttl_s}, ...]}` with `url` exactly as the upload returned. Never re-host or crop. `img/photos.json` holds the counts the live doc's `photos` also carries.
5. Verify: ArtifactData `get`, `collection:"live"`, `doc_id` = first id in `out/hourly/report.json` `doc_ids`; its `run` equals report.json `run`.

## (d) Morning (overwrites fixed docs, so it needs versions)

Rules for this section: run every command from `w/engine` in the FOREGROUND with the default Bash timeout (no `run_in_background`, no `&`). Do not end your turn until step 10 is done; a scheduled session ends with your turn and kills anything still running. `URL` = the Watchman artifact URL from the task prompt. On ANY failure that a single retry does not fix, go to step F.

1. `python3 run_morning.py start` (add `--static-once` only on the first ever run, or when asked). Returns at once; the engine (5-9 min) runs detached and logs to `out/morning.log`.
2. `python3 run_morning.py wait` -- blocks up to 270 s. `RUNNING` = call it again (expect 1-3 calls). `DONE` = engine exit 0 and tests pass. `FAILED step N: ...` = go to F with that text.
3. Versions: for every collection named in `out/morning/collections.txt` (one name per line), ArtifactData `action:"list"`, `url:URL`, `collection:<name>`, `out_dir:"out/lists"`, `query:{"limit":1000}` (follow `next_cursor` if given). Each result line shows `"<doc_id>" ... version N`. A collection with no docs yet is fine.
4. Write `versions.json` with the file-write tool: `{"<collection>/<doc_id>": N, ...}` for every doc those results list.
5. `python3 apply_versions.py --out out/morning --versions versions.json && python3 run_morning.py writes`. This prints one line per `writes_NNN.json` file (in `out/morning/` and `out/morning/hourly/`).
6. For each `out/morning/writes_NNN.json` in numeric order: Read the file and pass its JSON array, unchanged, as ArtifactData `action:"batch"`, `url:URL`, `writes:<array>`. Each entry is short (`file_path` points at the doc's data); never inline the data. If a write is refused for a stale version: re-list that collection, update versions.json, re-run step 5 and re-send only the files not yet accepted.
7. Images: `out/morning/img/manifest.json` lists `{id, file, credit, license, src_url, taken}` (`file` is relative to `out/morning/`, e.g. `img/<id>.jpg`). Upload with the Artifact tool (`url:URL`, `asset:true`, `file_paths`, up to 25 per call). Then write doc `img/index` (ArtifactData `set`, collection `img`, `if_version` from step 3 if it exists) = `{"images":[{id, url, credit, license, src_url, taken}, ...]}` with `url` exactly as the upload returned. Build that JSON with python into a file and pass `file_path`.
8. Verify: ArtifactData `get`, collection `meta`, doc_id `run`; its `run` equals `out/morning/report.json` `run`.
9. Live doc (M4): for each `out/morning/hourly/writes_NNN.json`, ArtifactData `batch` as in step 6 (new `live/<YYYY-MM-DD>T<HHMM>` docs, no versions). Then for `out/morning/hourly/img/manifest.json`: reuse the step-7 upload url of every id also in `out/morning/img/manifest.json`, upload only the others, and write ONE new doc `img/h<same stamp>` = `{"images":[{id, url, credit, license, src_url, taken, posted, publisher, width, height, ttl_s}, ...]}`. Verify with `get` of `live/<stamp>` that its `run` equals report.json `run`. If report.json `live` is null, skip this step (a warning says why).
10. Status: `python3 run_morning.py status --step done`, then ArtifactData `set` collection `meta`, doc_id `run_status`, `file_path:"out/run_status.json"`, `if_version` = its version from step 3 (omit if it did not exist). Finish with one line: `morning ok <run>`.

F. Failure (the safeguard, so a failed run is never silent): `python3 run_morning.py status --step <N> --error "<short error text, no secrets>"`, then ArtifactData `get` collection `meta` doc_id `run_status` (absent = new) and `set` it with `file_path:"out/run_status.json"` and that `if_version`. Then finish with one line: `morning failed at step <N>: <error>`. `meta/run_status` = `{ok, step, error, run, at, label}`; `ok:false` there means the last run failed at `step`.

## What the engine now does (data fixes, 2026-10-31)
- Heads of government: official page first (report.json `official_heads` shows what each page returned); Wikidata only as a labelled fallback (`who_runs.kind` = official, crowd-edited or not measured).
- NWS alerts: geometry from `affectedZones` (each zone fetched once per run, polygon at most 200 points); a failed zone leaves `place.geom: null` plus `place.geom_reason`. Same event type and office within 6 h is one item with `count` and `areas[]`.
- Titles and place names are never cut. Every item carries `touches_you {yes, how}`. The hourly live doc also holds `news:[clusters]` from the last 2 h.
- Tests added: heads, nws_extent, no_truncation, touches_you, nws_dedupe, live_news (hourly), brief_skeleton (morning). `python3 test_engine.py --out DIR [--out2 DIR2] --demo` shows each failing on bad input, then passing.
- 2026-10-31 (r3, data-truth fixes): `touches_you` is strict. Yes only for Marion County / Indiana items; physical hazards in Indiana, IL/OH/KY/MI or within 300 km of Indianapolis; national US presidential documents, proposed rules and US sanctions; US-wide gas, benefit, tax, rate or jobs stories. A country mention or a keyword alone is never enough, and foreign items need a stated US effect. `how` is a short fact read from the item. News cluster `truth` follows CONTRACT: confirmed = at least 2 distinct publisher hosts (www. stripped, registrable domain), single = exactly 1; the old extra "2 independent origins" gate that labelled wire-syndicated stories "single" is gone, and sources are now one per host. Tests added: touches_you_strict, truth_consistent (both in `--demo`).

## Photos (P10, 2026-11-01)
- R2-pub: news items get the preview picture the publisher shipped in its own feed (media:content / enclosure / media:thumbnail), credited to the publisher, `license: "publisher preview, linked"`, `src_url` = the article (pages always link through). Never an article page; never a publisher listed in `data/pub_photos_declined.txt` or whose feed is blocked.
- Gates: width >= 480, aspect 1:1-2:1, luminance sigma >= 12, no logo/flag/seal URL, same URL on > 2 items = banner. Stored (M2): <= 1280 px long side (never up-scaled), JPEG q 80 -> 60, <= 180 KB as an asset (160 KB when inlined as a data URI in a db doc), sha-deduped, ttl 7 d. Budget 150 fetches per run (robots, pages and images).
- M2 og:image (2026-11-01, Fable M2-JUDGE §4): ONLY for a top news item whose feed carries no picture, one GET of the linked article page, streamed and closed at `</head>` (8 s, UA "Watchman/1.0 (+link preview)"), robots.txt read once per host and obeyed, then the publisher's own `og:image` > `og:image:secure_url` > `twitter:image`. Never a publisher in `imgfeeds.BLOCKED_PUBLISHERS` (npr.org; aljazeera.com, whose robots.txt states its terms forbid automated scraping) or `data/pub_photos_declined.txt`, never a host that answered 401/403/451 or a bot wall this run, never a paywalled host (`PAYWALL_HOSTS`) or a page whose head says subscriber-only / redirects to login. Same gates as feed pictures plus a 600 px long-side floor and a strict image/* content type; robots, page and image requests all count in the 150-fetch budget. Credit = publisher, `image.via = "og"`, `image.link` = the article. Stories are never ranked or chosen by having a picture. Counts: `news_feed`, `news_og`, `news_matched_pct`, `og_pages`, `og_robots_read`, `blocked_hosts`.
- M2 feeds read hourly (each verified to ship a media picture on every item): PBS NewsHour, Guardian US, Sky News world, NBC News, BBC US & Canada, WTHR, WISH-TV.
- R2-gov: a record gets a photo only from its own issuer (White House feed picture on whitehouse.gov; NASA Image Library for nasa.gov). R3 (Wikimedia) stays on place pages.
- Counts: `meta/run.photos` (morning) and the live doc's `photos` (hourly) = {fetched, attached, stored, rejected{reason:n}}. `meta/run.cadence_s` = 3600 (`mode_period_s` = the mode's own period).
- After a real run: `python3 verify_live.py DB.json` (M4: reads what the UI renders, whichever mode wrote it -- all news/<date> clusters newest first; lead = most members; >= 80 % of the newest 30 matched; a photo in every hour with >= 5 items; newest live/* and newest run finished <= 70 min before now, measured).
- M4 photos (morning): clusters get a picture attempt in the order the page shows them (brief refs, the 40 newest, the 40 most-reported, then by publishers; `photo_targets`), top 150 under a 320-fetch budget, feed pictures fetched in parallel (8 workers, per-host gap kept). A cluster whose feed pictures all fail a gate now also gets the og:image pass, and the og pass reads up to 3 member pages (one GET each) before giving up. Blocked, declined and paywalled publishers are still never read; nothing is ranked by having a picture.

## Notes
- A failed source shows in report.json and meta/health (hourly: in the live doc `health`) as empty, blocked or error; nothing is filled in for it.
- Limits: db 100 MB / 25,000 docs. Hourly adds one small doc per run, so prune old `live/*` docs when asked.
- Date-keyed morning docs (events, wire, news, brief) are new each day; earlier-date ones already exist, so their collections are in collections.txt too.
- Text (improve pass 2, 2026-10-31): one sentence splitter that survives "U.S.", "Gov.", initials, "M5.1" and decimals (`sentences()`); Wikipedia current-event titles use it instead of `split(". ")`, so no title ends "...that U.S". Quake titles read "M5.1 earthquake in the Balleny Islands region" / "M4.5 earthquake 147 miles ESE of Zyryanka, Russia" (no dash, miles). Brief `so_what` is built from the item's facts (`why_here`: touches you or stake, where, who says so), never its headline. Test `text_split` covers all three; `--demo` shows it failing on a cut title and an old-shape quake title, then passing.

- 2026-10-31 (r7, engine defects from VERIFY-6):
  - News clustering is stricter: an article joins a cluster only if title similarity holds AND no member names a different place/actor (`event_conflict`: differing sub-place locators such as "Eastern Region" vs "Riyadh region", or each side naming a place/actor the other never mentions), within 18 h of the newest member and a 30 h cluster span (`EVENT_WINDOW_H`, `EVENT_SPAN_H`). Under-merges on purpose. Same corpus, old vs new rule: 616 clusters (64 confirmed, 552 single) became 658 (53 confirmed, 605 single); the Eastern Region / Riyadh drone cluster is now two single items.
  - `bls`: HTTP 200 with REQUEST_NOT_PROCESSED "daily threshold ... reached" is the keyless v1 API quota, not a parser failure; status is now `blocked` with that reason (a non-JSON 200 page is also `blocked`). No data is invented; `cpi_bls` is carried if fresh enough, else absent.
  - Gas: `gas_us` (EIA NUS) and `gas_midwest` (EIA R20, PADD 2) are different series that coincide on the latest week ($4.269, 2026-10-26) and agree on 1 of 400 dates. Nothing was mislabelled; each now carries `coincides_with {id, name, same_weeks, compared_weeks, note}` so the page can say so (`flag_coincident_series`).
  - Health: `meta/health`, `meta/run` and the hourly live doc head now carry `run`, `mode`, `total`, `ok` and `label` ("29 of 31 hourly sources returned data" / "62 of 75 morning sources returned data"). Hourly health never reuses morning totals. Old fields (`ok_sources`, `total_sources`) kept.
  - Tests added (both in `--demo`): `cluster_same_event`, `health_mode`.
